# L6 UI (Blade screens) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the deleted React SPA with a server-rendered Blade UI over the existing Laravel domain: staff and inventor screens, from `DESIGN.md` tokens, with no new runtime dependency except Dusk (dev-only) for the browser smoke suite.

**Architecture:** Blade views + Tailwind v4 theme tokens, rendered by thin controllers that call the L1–L5 domain modules directly. Filtering, pagination, tabs and deep links live in the URL; every mutation is a real `<form>` posting to an *existing* JSON route, which is extended with one `expectsJson()` branch to redirect-and-flash for HTML. JavaScript (~40 lines in `resources/js/app.js`) only opens the confirmation `<dialog>`s, the mobile drawer and dismisses toasts.

**Tech Stack:** Laravel 13 · PHP 8.3 · Blade · Tailwind v4 (`@theme` tokens) · Vite 8 · Pest 4 · Laravel Dusk (dev).

**Spec:** `docs/superpowers/specs/2026-10-18-l6-ui-design.md` — the plan argues from the spec, so read both.

## Global Constraints

- Baseline on the L5 head (`2f6c18e`): **399 tests / 1174 assertions green**. No existing test may be deleted or weakened; the only exception is `tests/Feature/ExampleTest.php`, which changes because `/` stops returning 200.
- **JSON contracts are frozen.** Every existing JSON response body and status stays byte-identical after negotiation. The existing suite is the proof.
- **No schema change, no migration.**
- **Dependencies:** the only new dependency is `laravel/dusk` (dev, Task 16). No new runtime/npm dependency. (Approved with the spec; issue #70 requires the Dusk suite.)
- **TDD always:** write the failing test, watch it fail, implement the minimum, watch it pass, commit. One test at a time.
- Run tests from `backend/`: `php artisan test --compact --filter='…'` or `vendor/bin/pest tests/Feature/XTest.php`. Full suite: `cd backend && php artisan test --compact`.
- Before every commit run: `cd backend && vendor/bin/pint --dirty --format agent`.
- All Artisan commands get `--no-interaction`.
- **Naming:** page controllers `App\Http\Controllers\Admin\*` and `App\Http\Controllers\Portal\*`; page views `resources/views/admin/…` and `resources/views/portal/…`; anonymous components `resources/views/components/ui/*` (`<x-ui.button>`), layouts `resources/views/components/layouts/*` (`<x-layouts.app>`).
- **Route guards:** `/admin/*` = `auth` + `role:director,md`; `/admin/users` = `auth` + `role:md`; `/user/*` = `auth` + `role:user`; `GET /notifications` (JSON) = `auth`.
- **User-facing copy** for login failures is fixed by the spec §5.1 — use those exact strings.
- **Flash keys:** `status` (success), `warning` (grant without document), `$errors->first('form')` (domain failure), `$errors->first('<field>')` (validation).
- **Nav grows with the pages** (Task 6 adds Patents, 11 adds Users, 12 adds My Patents, 15 adds Notifications) so a nav link never points at a route that does not exist yet.
- Deviation from the spec's path only: the patent-table presenter lives at `App\Support\PatentTable` (the spec said `App\Http\Presenters`; `app/Support` already exists and `AGENTS.md` forbids new base folders without approval).
- `resources/views/welcome.blade.php` is deleted in Task 3.

## Review Focus

The five input classes most likely to bite a person using this software — each has its test named in parentheses, in the task that owns the code:

1. **A guest or wrong-role browser request must never receive a JSON body** — it redirects to `/login` or renders the styled 403 page. (Task 4: `HtmlAccessTest`.)
2. **JSON callers must keep byte-identical responses** after the negotiation refactor; a stale API client must not start receiving a 302. (Task 4: `JsonContractPreservedTest`; every later task re-runs the touched controller's existing tests.)
3. **A filing step or status change attempted in the wrong state must come back as a form error with no state change** — the panel's action grouping is a heuristic, not a guard. (Task 9: `AdminFilingPanelTest`.)
4. **An inventor must never see or fetch another inventor's patent**, and must not download a document that is still pending or fork an open request. (Tasks 13, 15: `PortalPatentDetailTest`, `PortalNotificationsTest`.)
5. **Uploads:** a file PHP rejects for size must flash the 413 message rather than 500, and a hostile filename must be rendered escaped. (Tasks 10, 15: `AdminDocumentsPanelTest`, `HtmlEscapingTest`.)

- [ ] **Step 5: Add the theme helper and share the theme with every view**

Create `backend/app/Support/Theme.php`:

```php
<?php

namespace App\Support;

use Illuminate\Http\Request;

/**
 * Light/dark preference. Per-browser, not per-user: the choice lives in a
 * cookie so the server can render the right first paint (spec §7.3).
 */
final class Theme
{
    public const COOKIE = 'blitto-theme';

    public const LIGHT = 'light';

    public const DARK = 'dark';

    public static function fromRequest(Request $request): string
    {
        return $request->cookie(self::COOKIE) === self::DARK ? self::DARK : self::LIGHT;
    }

    public static function isDark(Request $request): bool
    {
        return self::fromRequest($request) === self::DARK;
    }
}
```

In `backend/app/Providers/AppServiceProvider.php`'s `boot()`, add at the top of the method:

```php
        View::composer('*', function (View $view): void {
            $view->with('theme', Theme::fromRequest(request()));
        });
```

with the imports `use App\Support\Theme;`, `use Illuminate\View\View;`.

```js
// The whole client-side surface: confirmation dialogs, the mobile drawer and
// toast dismissal. Everything else is server-rendered (spec §7.4).

document.addEventListener('click', (event) => {
    const opener = event.target.closest('[data-dialog-open]');

    if (opener) {
        event.preventDefault();
        const dialog = document.querySelector(opener.dataset.dialogOpen);

        if (dialog) {
            dialog.showModal();
        }

        return;
    }

    const dismiss = event.target.closest('[data-toast-dismiss]');

    if (dismiss) {
        dismiss.closest('[data-toast]')?.remove();

        return;
    }

    const toggle = event.target.closest('[data-drawer-toggle]');

    if (toggle) {
        const drawer = document.querySelector('#sidebar');

        if (drawer) {
            const open = drawer.classList.toggle('hidden');
            toggle.setAttribute('aria-expanded', String(! open));
        }
    }
});
```

Create `docs/adr/0006-blade-not-livewire-for-the-ui-layer.md`:

```markdown
# ADR 0006: Blade, not Livewire, for the L6 UI layer

## Status
Accepted

## Context
The migration design (§5, §8) named "Blade + Livewire 4" as the stack, and
`livewire/livewire` 4.4.7 does declare `illuminate/* ^13.0`, so the dependency is
available. L6 then looked at what the screens actually need: tables with filters
and pagination, detail pages, and forms whose mutations already exist as tested
JSON endpoints. Every one of those is a server round-trip.

## Decision
The UI is Blade + Tailwind with the URL as state (filters, pagination and tabs
are query strings) and mutations as `POST → redirect → flash` against the
existing controllers. JavaScript is ~40 lines in `resources/js/app.js` for the
confirmation `<dialog>`s, the mobile drawer and toast dismissal. No Alpine, no
Livewire, no new runtime or npm dependency; `laravel/dusk` (dev-only) is added
for the browser smoke suite.

Livewire was rejected because it adds a PHP dependency and a second testing
paradigm (`Livewire::test`) to cover interactions the domain endpoints already
serve, and because its payoff — live-updating components — is not something any
screen in scope needs. Alpine was rejected because four interactions do not earn
a dependency when Vite already builds `app.js`.

## Consequences
Every page behaviour is assertable by a Pest HTTP test, and the browser suite is
small enough to run in its own CI job. If a future screen genuinely needs
live-updating data, the decision to revisit is this one — not a rewrite.
```

```php
    public function store(Request $request): JsonResponse|RedirectResponse
    {
        $email = EmailPolicy::normalize((string) $request->input('email', ''));
        $password = (string) $request->input('password', '');

        if (! EmailPolicy::isInstitution($email)) {
            return $this->failure($request, 'Enter a valid institution email address.', 403, 'Institution email required');
        }

        if ($this->throttle->locked(AttemptThrottle::LOGIN, $email)) {
            $response = $this->failure($request, 'Too many attempts. Please wait a few minutes and try again.', 429, 'Too many login attempts');

            return $request->expectsJson() ? $response->header('Retry-After', '600') : $response;
        }

        if (! Auth::attempt(['email' => $email, 'password' => $password])) {
            $this->throttle->recordFailure(AttemptThrottle::LOGIN, $email);

            return $this->failure($request, 'Incorrect email or password. Please try again.', 401, 'Invalid credentials');
        }

        $this->throttle->clear(AttemptThrottle::LOGIN, $email);
        $request->session()->regenerate();

        $this->audit->record('auth:login', actor: Auth::user(), ipAddress: $request->ip());

        if ($request->expectsJson()) {
            return response()->json(Auth::user(), 200);
        }

        return redirect()->intended(HomeFor::path(Auth::user()));
    }

    /**
     * One failure, two representations: JSON keeps the status and body it has
     * always returned; an HTML form comes back with the field error.
     */
    private function failure(Request $request, string $message, int $status, string $jsonMessage): JsonResponse|RedirectResponse
    {
        if ($request->expectsJson()) {
            return response()->json(['message' => $jsonMessage], $status);
        }

        return back()->withInput($request->only('email'))->withErrors(['email' => $message]);
    }
```

```php
         * One failure, two representations (spec §6). JSON keeps the exact
         * status and body it has always returned; an HTML request comes back

        $domainError = function (

            Request $request,
            int $status,
```

```php
namespace App\Http\Controllers;

use App\Support\Theme;
use Illuminate\Http\RedirectResponse;
use Illuminate\Http\Request;

/**
 * A form post rather than a link: the toggle changes state and must be
 * CSRF-protected (spec §7.3).

final class ThemeController extends Controller
{
    public function __invoke(Request $request): RedirectResponse
    {
        $validated = $request->validate([
            'theme' => ['required', Rule::in([Theme::LIGHT, Theme::DARK])],

        return back()->withCookie(cookie(

            value: $validated['theme'],

            sameSite: 'lax',
        ));
    }
}
```

```php
<?php

namespace App\Support;

use App\Models\Application;
use Illuminate\Contracts\Pagination\LengthAwarePaginator;
use Illuminate\Support\Collection;

/**
 * Presentation only: search, status filter and paging over a collection the
 * domain already scoped (spec §8.2.2). No business rule lives here.
 */
final class PatentTable
{
    public const PER_PAGE = 15;

    /**
     * @param  Collection<int, Application>  $applications
     * @return Collection<int, Application>
     */
    public static function filter(Collection $applications, ?string $query, ?string $status): Collection
    {
        $needle = mb_strtolower(trim((string) $query));
        $status = ($status === null || $status === 'all' || $status === '') ? null : strtoupper($status);

        return $applications
            ->when($needle !== '', fn (Collection $rows): Collection => $rows->filter(
                fn (Application $application): bool => str_contains(
                    mb_strtolower(implode(' ', array_filter([
                        $application->title,
                        $application->inventor_name,
                        $application->inventor_email,
                        $application->technology_area,
                        $application->application_number,
                    ]))),
                    $needle,
                ),
            ))
            ->when($status !== null, fn (Collection $rows): Collection => $rows->filter(
                fn (Application $application): bool => $application->status === $status,
            ))
            ->sortByDesc('created_at')
            ->values();
    }

    /**
     * @param  Collection<int, Application>  $rows
     */
    public static function paginate(Collection $rows, int $page, string $path): LengthAwarePaginator
    {
        $page = max(1, $page);

        return new LengthAwarePaginator(
            $rows->forPage($page, self::PER_PAGE)->values(),
            $rows->count(),
            self::PER_PAGE,
            $page,
            ['path' => $path],
        );
    }
}
```

```php
     * @return Collection<int, Notification>
     */
    public function forUser(User $user): Collection
    {
        return Notification::query()
            ->where('recipient_email', $user->email)
            ->orderByDesc('sent_at')
            ->orderByDesc('id')
            ->limit(self::MAX_ROWS)
            ->get();
    }

    public function countFor(User $user): int
    {
        return Notification::query()->where('recipient_email', $user->email)->count();
    }
}
```

- [ ] **Step 3: Keep `phpunit.dusk.xml` and `.env` pointing at the same database**

The Dusk runner starts `php artisan serve` as a **separate process**. That child
does not read `.env.dusk.local`: Laravel's `checkForSpecificEnvironmentFile()`
loads `.env.{APP_ENV}`, so with `APP_ENV=local` it loads `.env`. Overriding
`DB_DATABASE` only in `phpunit.dusk.xml` would therefore leave the browser
hitting a *different* database from the one `migrate:fresh --seed` populated.

So: do **not** override the database in `phpunit.dusk.xml`. Leave the generated
environment block, and only ensure these two values are present:

```xml
    <php>
        <env name="APP_ENV" value="local"/>
        <env name="APP_URL" value="http://127.0.0.1:8000"/>
    </php>
```

Both processes then use `.env` — `database/database.sqlite`, `SESSION_DRIVER=database`
and `CACHE_STORE=database` (their tables exist from L0) — and CI overrides
`DB_DATABASE` in the job environment instead, which both processes inherit
(Task 18).
